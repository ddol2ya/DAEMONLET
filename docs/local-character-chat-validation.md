# 로컬 캐릭터챗 v2 구현·검증 기록

2026-09-23. 기반은 main `e0b555d142fc4c6dc46897d94a4b6e9c5fc5b8ed`, 기능 브랜치는 `codex/local-character-chat-v2`다. 벤치마크 브랜치는 병합하지 않았다. 기존 main의 미커밋 변경을 보존했다. 이 문서의 로컬 검증 뒤 사용자 요청으로 기능 브랜치 PR을 준비했으며, 병합·릴리스는 별도다.

## 구현 범위

데스크톱에 있는 캐릭터 옆에 입력 가능한 말풍선을 띄운다. 기존 캐릭터 renderer를 사용하고 별도 캐릭터 미리보기를 만들지 않는다. 모델 설치/가져오기, 선택, JSON text 스트리밍, 실제 서버 중단, 재시도, 캐릭터별 대화/명시적 기억 저장을 연결했다. 메뉴에서 Codex 대화로 전환하면 로컬 말풍선이 닫히며 Codex 작업 자체는 취소하지 않는다.

주요 제품 변경은 `electron/main/character-chat`, `electron/shared/character-chat-*`, `electron/preload/character-chat-preload.ts`, `src/character-chat`, `AppController`, `PetApp`이다. 기존 behavior/renderer에는 대화 연출 소유권과 시각 모션 제한만 추가했다. 팩 parser/validator와 실제 `build-independent-payload.mjs` → `export-pack.mjs` 경로는 같은 의미 검증기를 사용한다. 제작 스킬의 내보내기 지침도 갱신했다.

앱은 특정 캐릭터나 포즈 ID를 하드코딩하지 않는다. 팩이 선언한 phase/emotion/intent/intensity 규칙을 선택하고 지원되지 않는 의미/제스처는 정상 기본 자세로 돌아간다. 도구·셸·MCP·외부 평가 모델 권한은 제공하지 않는다. 예문/원작 설정/사용자가 저장한 기억/현재 대화는 별도 자료다.

## 실제 실행

- macOS 27.0, Apple M5 Max, 64 GiB, arm64 패키지 앱에서 실행했다. Windows/CUDA·최소사양 검증은 하지 않았다.
- 공식 Gemma 4 E4B와 12B QAT Q4_0 GGUF를 각각 UI로 가져오고 SHA-256 검증 후 생성했다. 두 모델을 동시에 적재하지 않았다.
- llama.cpp `391fac16460f15233a7740550d858ac96df3419d`, 정적 Release/Metal 빌드. runtime catalog에 고정한 바이너리를 패키지에 넣었다. 모델과 외부 캐릭터 자산은 앱에 넣지 않았다.
- loopback 인증, context 8192, 출력 512 + 예약 256, slot 1, thinking off/reasoning budget 0, 전체 Metal offload, f16 KV, flash attention, batch/ubatch 512, checkpoint 1을 사용한다. 준비 시 실제 slot/context/offload/checkpoint 적용을 검사한다.
- 토키 v3 QA 팩, 토키 v4 1.0.2, 합성 A/B 모두 실제 앱 설치·선택·응답을 확인했다. A/B 교체 사이에 실행 중인 앱 코드나 전역 매핑을 수정하지 않았다.
- 12B와 E4B에서 생성 중 일부 대사가 나온 뒤 중단됨을 확인했다. 중단 후 소유 모델 프로세스가 종료되고 다음 요청이 복구됐다. v4에서는 새 대화·재시도·재시작 복원도 확인했다.
- 앱 정상 종료 후 해당 앱/모델 프로세스가 남지 않았다. 최종 패키지 재실행에서 v4 선택과 저장 이력이 복원됐다.

## 팩·제작 도구

토키 v3의 31개 포즈 ID와 원화/PSD/리그/작업·터치 자료를 보존했다. 별도 1.3.1 로컬 후보에서 persona와 chat metadata만 보완했다. 생성중/중립 설명/수줍음/공감에 신규 4개 포즈를 연결했다. 나머지 포즈를 이름만으로 자동 확정하지 않았다. 기존 파일의 bytes/SHA를 대조한 업그레이드 보고서를 로컬에 보관한다. 공개 stable 팩은 바꾸지 않았다.

위키 근거는 인연 스토리 1–4, 대사, 작중 행적의 리오·C&C·최종편 구조, 히마리·에이미 관련 절을 읽고 새 추출본 위치와 함께 기록했다. 새 예문은 새로 쓴 예문이며 실제 사용자와의 기억으로 저장하지 않았다. 위키 원문과 캐릭터 자산/설정 산출물은 Git에 넣지 않았다.

사용자가 추가 요청한 토키 v4 1.0.2는 **원본 그대로** 시험했다. 이 팩에는 persona가 있지만 chat 의미 선언이 없다. 따라서 기본 자세와 해당 팩의 말투를 사용하는 legacy 호환 결과이며 감정 포즈 전환 성공으로 집계하지 않는다.

## 실패·제약·남은 확인

- OS 외부 연결 차단 시험용 Seatbelt 프로필은 외부 연결을 EPERM으로 차단했으나 Electron의 자식 GPU/network sandbox 초기화와 충돌하여 앱이 종료됐다. 보호 설정을 끄지 않았다. 설치 후 생성 경로는 로컬 API와 `--offline` runtime만 사용하지만, 네트워크가 실제 끊긴 환경의 완전한 앱 인수 결과는 아직 없다.
- Windows/CUDA 패키지/장비, 깨끗한 소비자 장비 첫 설치, 서명·공증·공개 배포는 미검증/미수행이다. 이 로컬 macOS 후보를 정식 릴리스로 부르지 않는다.
- UI의 네트워크 다운로드 전체 용량 전송은 반복하지 않았다. 정확한 기존 GGUF의 실제 가져오기는 통과했고 취소/이어받기/용량 부족/해시 오류는 작은 모의 전송 단위시험으로 확인했다.
- 모델이 요청한 표현을 항상 지키지는 않는다. v4 E4B 시험에서 영어 `barley tea` 기억을 부정확한 한국어 명칭으로 옮긴 사례와 긴 목록을 바로 답하지 않고 되묻는 사례가 있었다. 형식/동작 성공과 캐릭터 대화 품질은 별개이며 인간 품질 검수를 완료했다고 주장하지 않는다.
- 실제 31개 포즈 전체의 연속 대화 시각 QA, 모든 화면 배율/다중 모니터 위치, 생성 중 팩 업데이트/창 종료의 모든 네이티브 경합은 추가 확인 대상이다.

사용법과 개발 재현 명령은 [로컬 캐릭터챗](local-character-chat.md)에 있다. 원시 시험 대화와 자세한 A01–D07 결과, 사용한 팩 hash, 입력 근거, 로컬 앱/QA 팩 위치는 공개 Git 밖의 로컬 전달 보고서에 보관한다.

## 답변 포즈 유지 보완 (2026-09-23)

답변 준비는 첫 대사 전 800ms 지연 후 진입하며, 진입 완료부터 최소 900ms 유지한다. 첫 대사가 이미 도착했으면 아직 시작하지 않은 준비 포즈는 취소한다. 스트리밍과 최종 감정 포즈 사이의 불필요한 기본 자세를 제거했다. 답변 의미의 2.4초 자동 해제와 입력 focus/blur의 해제를 없애서 다음 요청까지 마지막 답변 자세를 유지한다. 중단·오류·모드/팩 변경은 지연된 자세까지 폐기한다. 비동기 리그 진입 시간과 오래된 callback도 회귀시험에 포함했다.

이 보완 후 전체 185개 시험 파일에서 1,840개 통과, 5개 조건부 skip이며 typecheck와 macOS 패키징도 통과했다.

## 말풍선 위치·크기 조절 보완 (2026-09-23)

상단 드래그와 오른쪽 아래 손잡이로 이동·크기 조절을 지원한다. 사용자 조작만 별도 로컬 layout 파일에 저장하고, 캐릭터 기준 상대 위치와 크기를 재실행 시 복원한다. 자동 화면 내 보정은 저장된 의도를 덮어쓰지 않는다. 메뉴에서 자동 배치/기본 크기로 초기화할 수 있다.

투명 창의 기본 이동 영역 대신 기존 소유 창 드래그 controller를 재사용했다. 네이티브 mouse-down 원점과 전달된 이벤트 좌표를 사용하며, 마우스 해제가 renderer의 begin IPC보다 먼저 도착한 경우에도 한 번만 commit한다. Esc/blur/창 닫힘은 미완료 조작을 취소한다. 기존 캐릭터 이동 경로는 기본 동작을 보존한다. 최소 크기에서 비어 있는 대화 안내가 잘리지 않도록 메시지 영역만 스크롤한다.

전체 186개 시험 파일, 1,849개 통과·5개 skip. 실제 macOS UI에서 350×360 → 370×380 확대와 위치 이동이 의도한 변화량으로 저장되는 것을 확인했다. 초기화·크기 제한·화면 보정·저장 순서는 단위시험으로 확인했다. Windows 네이티브 조절은 미검증이다.

최종 네이티브 확인에서 위치 +10/+5 이동 및 크기 370×380이 앱 재실행 후 복원됐으며, 확인 후 사용자의 이전 위치와 350×360 크기로 정확히 되돌렸다. 메뉴 버튼과 초기화 항목 표시도 확인했다.

## UI·팩 표시 이름과 PR 준비

상단 이름과 좌우 메시지·입력칸 중심으로 UI를 단순화했다. `chat.json.profile.displayName`을 대화창, 작업 말풍선의 물어보기 버튼, Side Chat 입력 안내와 persona 인물명에 사용한다. 팩 선택/관리 목록과 ID는 그대로 유지한다. 미설정·무효 optional 이름은 기존 팩 이름으로 복귀한다. 제작의 `models.json.chatProfile`과 export/upgrade-chat 경로도 이 필드를 검증·보존한다.

토키 v3 로컬 후보는 대화 연결을 20포즈·34규칙으로 확장한 뒤 이름만 보완하여 1.3.3으로 재포장했다. v4/v5는 1.0.3 이름 보완 후보를 만들었다. 원본 팩과 시각 자산은 유지했고 세 팩 모두 앱 UI로 설치해 버전 구분 목록과 대화 이름 분리를 확인했다. 팩 파일은 PR에 포함하지 않는다. 이는 전체 포즈 시각 검수나 공개 stable 업데이트가 아니다.

소스 빌드와 배포 패키징은 구분한다. Linux/Windows CI는 모델/네이티브 추론 파일 없이 소스를 검사한다. 실제 Forge 패키징은 대상 플랫폼·런타임 catalog·파일 SHA를 확인하며 없거나 불일치하면 중단한다. 현재 허용된 배포 대상은 macOS arm64다.

PR 준비 시 전체 186개 파일에서 1,852개 통과·5개 조건부 skip을 확인했다. 이후 추가한 실제 패키징 target/lock/hash/누락 보호 검사는 별도 4개 모두 통과했다. 최초 제한 환경의 전체 실행은 로컬 소켓 권한 때문에 실패했으며, 호스트 권한으로 재실행한 결과를 통과 수치로 기록했다. typecheck·source:check·소스 공백 검사도 통과했다. 원문 라이선스 2개의 EOF 빈 줄 경고는 고지 원문을 보존하기 위해 유지했다. native runtime staging을 일시 제외한 실제 production 소스 빌드와 `release:verify`도 통과하여, CI 소스 검증에 로컬 바이너리가 필요하지 않음을 확인했다.

## PR #22 리뷰 후 데이터 보존·복구 수정

검토 HEAD `e1f4aad`의 F1–F4는 기존 통과 수치와 별도로 재현 가능한 결함으로 취급했다. 모델 비교시험은 재개하지 않았다.

- **F1:** 서비스의 미초기화/초기화 중/준비 완료/실패/종료 상태를 분리했다. 읽기 전 또는 실패한 초기화의 기본값을 저장하지 않는다. 반복 close/dispose는 같은 종료 작업을 공유한다. 창을 닫는 동작은 서비스의 영구 종료와 구분한다. 위치 파일도 읽고 실제로 변경한 경우에만 저장한다.
- **F2:** 후보 캐릭터·페르소나·표시 이름·의미·대화를 별도로 준비하고 화면 적용과 저장 후 한 번에 반영한다. 실패 시 이전 화면으로 복원하며 복원 실패는 입력을 차단한다. 전환 중 send/retry를 막고, 요청·저장 경계에서 대화 소유자와 revision/epoch를 확인한다. 동일 ID 팩 갱신은 기존 대화를 유지한다. 첫 진입은 현재 데스크톱의 캐릭터를 우선한다.
- **F3:** 대화/메시지/파일 용량 한도를 요청 전에 확인한다. 사용자 변경은 후보 데이터를 저장한 뒤 반영하며 저장 실패 시 이전 상태를 보존한다. 생성 취소와 저장을 분리하여 실패 뒤 삭제가 가능하다. 최종 응답 저장 실패도 성공으로 표시하지 않는다. 저장용 임시 파일은 실패 후 정리한다.
- **F4:** 완결 JSON의 안전한 대사와 선택적 감정 정보를 따로 검증한다. 감정 정보만 잘못되면 낮은 강도의 중립 의미로 대체하고 내부 진단을 기록한다. 대사는 완료 상태로 보존하여 다음 턴에 포함한다. 잘린 JSON·생각 태그·미허용 실행 필드·빈 대사는 여전히 실패한다.

전체 **188개 테스트 파일, 1,888개 통과·5개 조건부 skip**, typecheck, source:check, macOS 패키징 통과. 초기화 중/실패 후 종료, 반복 close/dispose, 화면 적용 및 persona 읽기·파싱 실패, 제거/교체된 팩, 빠른 전환과 전환 중 입력, 저장 실패 뒤 삭제, 500대화·4,000메시지·32MiB 경계, 잘못된 의미 뒤 다음 입력을 회귀시험했다. 32MiB 시험의 최초 Buffer 심층 비교가 테스트 프로세스 메모리를 과도하게 사용해 바이트 비교로 고쳤으며, 제품 모델 OOM 실측으로 집계하지 않는다.

실제 Mac 앱 검증은 원본 대화·기억·위치 파일을 별도 백업한 뒤 복제 프로필에서 수행했다. 캐릭터챗을 열지 않은 앱 실행→정상 종료 후 대화와 위치 파일의 SHA-256이 그대로인 것을 확인했다. 실패 주입·저장 상한·잘못된 모델 metadata는 합성 제품 회귀시험이며 네이티브 UI에서 그 오류들을 모두 재현했다고 주장하지 않는다.

Windows Actions 통과는 소스 검증이다. 이 PR의 native runtime 배포 대상은 여전히 macOS arm64/Metal이며, 기존 공개 Windows 0.7.2 배포를 이 후보로 대체하지 않는다. Windows 신규 패키징, 완전한 네트워크 단절 환경, 서명·공증과 일반 릴리스는 별도 확인이 필요하다.

같은 복제 프로필의 패키징 앱에서 12B 한 턴의 실제 스트리밍·완료 저장, 말풍선 닫기→재열기, v3→v4→v3 전환 후 캐릭터별 대화 복원을 확인했다. 실패한 화면 적용과 잘못된 metadata를 실제 모델 출력으로 유도한 시험은 하지 않았다. 원본 프로필은 복원·덮어쓰기하지 않았으며, 시험 중 원본에서 발생한 별도 변경도 유지했다.
